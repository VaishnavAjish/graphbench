1. Resource Parity Principle

CognoDB's free c0 tier is the baseline instance: 0.5 vCPU (burstable) / 256 MB RAM / 1 GB disk. No competing database is granted a higher hardware ceiling. Every self-hosted container in Track B is hard-capped at --cpus=0.5 --memory=256m.

Platform Track Hardware Limit Parity Strategy
CognoDB Cloud Track A (Cloud) 0.5 vCPU / 256MB Baseline specification
Neo4j AuraDB Free Track A (Cloud) Aura Free shared Matched to lowest free cloud tier
Memgraph Track B (Docker) 0.5 vCPU / 256MB Strict Docker resource caps
FalkorDB Track B (Docker) 0.5 vCPU / 256MB Strict Docker resource caps
ArangoDB Track B (Docker) 0.5 vCPU / 256MB Strict Docker resource caps

2. Strict Timing & Statistical Policy

01
Cold Sample (10 iters) Captured immediately upon connecting before cache warm-up. Never blended into warm numbers.
02
Warm-up Phase (20 iters) JIT execution and driver connection pools warm up. Timings are completely discarded.
03
Warm Sample (120 iters) The measured headline sample. Timer wraps ONLY the driver call; argument RNG is excluded.
Nearest-Rank Percentiles: Percentiles (p50, p95, p99) use nearest-rank on the sorted distribution rather than synthetic interpolation.

Cypher vs. AQL Logical Equivalents

Every database executes the exact same logical graph query. Where query languages differ (Cypher vs AQL), equivalent constructs with identical index utilization and limit semantics are used:

1. Point Lookup

Cypher (Neo4j / Memgraph / Cogno / Falkor) 
MATCH (n:Person {uid: $uid})
RETURN n.uid AS uid
AQL (ArangoDB) 
FOR p IN person
  FILTER p.uid == @uid
  RETURN p.uid

2. Secondary Filtered Scan (Indexed)

Cypher 
MATCH (n:Person)
WHERE n.bucket = $b
RETURN n.uid AS uid LIMIT 500
AQL 
FOR p IN person
  FILTER p.bucket == @b
  LIMIT 500
  RETURN p.uid

3. N-Hop Traversal (with Limit Cap)

Cypher 
MATCH (a:Person {uid: $uid})-[:FOLLOWS*2..2]->(b:Person)
RETURN DISTINCT b.uid AS uid LIMIT $lim
AQL 
FOR v IN 2..2 OUTBOUND @start_node follows
  OPTIONS { uniqueVertices: 'global' }
  LIMIT @lim
  RETURN DISTINCT v.uid

4. Group-By Aggregation

Cypher 
MATCH (n:Person)
RETURN n.bucket AS bucket, count(*) AS c
ORDER BY c DESC LIMIT 20
AQL 
FOR p IN person
  COLLECT b = p.bucket WITH COUNT INTO c
  SORT c DESC
  LIMIT 20
  RETURN { bucket: b, count: c }
